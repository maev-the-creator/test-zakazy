# Настройка Google-таблицы, Apps Script и Telegram — пошагово

Инструкция для тех, кто ни разу не работал с Apps Script. Займёт 15–20 минут.
Что получится в конце: Google-таблица с листами «Настройки», «Даты», «Заявки», «Журнал»; веб-адрес (URL), который вы вставите в сайт; заявки с сайта будут падать в таблицу и приходить в Telegram.

> **Словарик.**
> **Apps Script** — встроенный в Google «мини-сервер»: маленькая программа, которая живёт рядом с таблицей.
> **Развертывание (деплой)** — публикация этой программы по ссылке, чтобы сайт мог к ней обращаться.
> **Свойства скрипта** — секретные настройки программы (как сейф). Туда кладём токен бота, чтобы он не попал на сайт.

Понадобится: аккаунт Google (лучше обычный @gmail.com — в корпоративных аккаунтах администратор может запретить доступ «для всех»), Telegram, токен бота и chat_id группы (их пришлёт разработчик).

---

## Шаг 1. Создать таблицу

1. Откройте [sheets.new](https://sheets.new) — создастся пустая таблица.
2. Нажмите на «Новая таблица» вверху слева и назовите её, например, **«<Название> — заявки»**.

✅ Должно быть: пустая таблица с листом «Лист1».

## Шаг 2. Открыть Apps Script

1. В меню таблицы: **Расширения → Apps Script**.
2. Откроется новая вкладка — редактор кода. Слева файл `Код.gs` (или `Code.gs`), в нём пустая функция `myFunction`.

✅ Должно быть: редактор с проектом «Проект без названия».

3. Нажмите «Проект без названия» вверху и назовите проект **«ORDER FORGE — <Название>»**.

## Шаг 3. Вставить код

1. Откройте в репозитории файл [`apps-script/Code.gs`](../apps-script/Code.gs) → кнопка **Raw** (или «Копировать») → выделите всё (Ctrl+A / Cmd+A) и скопируйте.
2. В редакторе Apps Script выделите всё в `Код.gs`, удалите и вставьте скопированное.
3. Нажмите значок дискеты **«Сохранить проект»** (или Ctrl+S / Cmd+S).

✅ Должно быть: сверху в файле комментарий «ORDER FORGE — «Окно заказов» для кондитерской», ошибок нет.

## Шаг 4. Часовой пояс — Москва

1. Слева нажмите шестерёнку **«Настройки проекта»**.
2. Поставьте галочку **«Показывать файл манифеста "appsscript.json" в редакторе»**.
3. Вернитесь в **«Редактор»** (значок `< >` слева). Появится файл `appsscript.json`.
4. Откройте его, удалите всё и вставьте содержимое [`apps-script/appsscript.json`](../apps-script/appsscript.json). Сохраните.

✅ Должно быть: в `appsscript.json` строка `"timeZone": "Europe/Moscow"`. (Если не получилось — в «Настройках проекта» выберите часовой пояс «(GMT+03:00) Москва».)

## Шаг 5. Свойства скрипта — ДО запуска setup()

1. В редакторе: шестерёнка **«Настройки проекта»** → прокрутите вниз до **«Свойства скрипта»**.
2. Нажмите **«Добавить свойство скрипта»** и заполните строки (названия — латиницей, как в таблице):

   | Свойство | Значение |
   |---|---|
   | `SITE_URL` | адрес сайта кондитерской, без `/` в конце: `https://tort-anna.vercel.app` |
   | `GITHUB_REPO` | репозиторий сайта: `ник-владельца/название`, например `anna-cakes/tort-anna-zakazy` |
   | `BAKERY_NAME` | название кондитерской (попадёт в «Настройки», сообщения Telegram и папку фото) |
   | `TELEGRAM_BOT_TOKEN` | вставьте токен бота (длинная строка вида `123456789:AA…`) |
   | `TELEGRAM_CHAT_ID` | вставьте chat_id группы (число со знаком минус, например `-1234567890`) |

   Пароль админки и ключ GitHub — шаг 11 (их можно добавить сразу сюда же).
3. Нажмите **«Сохранить свойства скрипта»**.

✅ Должно быть: строки в «Свойствах скрипта». Без `SITE_URL` и `GITHUB_REPO` `setup()` откажется работать и подскажет, что добавить. Здесь же позже появятся служебные `SPREADSHEET_ID`, `LAST_ORDER_NUMBER`, `PHOTO_FOLDER_ID`, `SCHEMA_VERSION` — их не трогайте.

> ⚠️ Токен нигде больше не пишите: ни в `config.js`, ни в код, ни в чаты. Тот, у кого есть токен, может писать от имени бота.

## Шаг 6. Запустить `setup()` — таблица оформится сама

1. В редакторе откройте `Код.gs`.
2. Вверху, рядом с кнопками «▷ Выполнить» и «Отладка», есть выпадающий список функций. Выберите **`setup`**.
3. Нажмите **«▷ Выполнить»**.

Первый раз Google попросит разрешения — это нормально:

4. Окно **«Требуется авторизация»** → нажмите **«Проверить разрешения»**.
5. Выберите свой аккаунт Google.
6. Появится экран **«Google не проверил это приложение»** (Google hasn't verified this app). Это потому, что программу написали вы, а не крупная компания. Нажмите внизу **«Дополнительные настройки»** (Advanced), затем **«Перейти на страницу «ORDER FORGE — <Название>» (небезопасно)»**.
7. Список разрешений: просмотр и изменение таблиц, доступ к Google Диску (для папки с фото-референсами), подключение к внешним сервисам (для Telegram). Нажмите **«Разрешить»**.
8. Внизу редактора появится «Журнал выполнения»: «Выполнение начато» → **«Выполнение завершено»**.

✅ Должно быть: в таблице появились листы **«Настройки», «Даты», «Заявки», «Журнал»** и листы админки **«Каталог», «Начинки», «Тексты», «Доступ»** (заполнены с сайта), шапки шоколадного цвета, жёлтые колонки (их меняете вы), на «Датах» — 45 дней вперёд. Пустой «Лист1» удалён.

> Повторный запуск `setup()` безопасен: ваши значения, даты и заявки не трогаются, добавляется только недостающее.

### Проверка Telegram

1. Убедитесь, что бот **добавлен в группу** (в группе: «Добавить участника» → найдите бота по имени).
2. В редакторе выберите функцию **`testTelegram`** → **«▷ Выполнить»**.

✅ Должно быть: в группу пришло «✅ ORDER FORGE подключён». Если нет — см. «Если что-то пошло не так» внизу.

## Шаг 7. Опубликовать веб-приложение (развертывание)

1. Справа вверху синяя кнопка **«Начать развертывание» → «Новое развертывание»**.
2. Рядом с «Выберите тип» нажмите шестерёнку → **«Веб-приложение»**.
3. Заполните:
   - **Описание:** `Окно заказов v1`
   - **Запуск от имени:** **«Я (ваш@gmail.com)»** — программа работает с таблицей от вашего имени.
   - **У кого есть доступ:** **«Все»** — чтобы сайт мог отправлять заявки без входа в Google. (Это доступ к адресу программы, а не к таблице — таблицу по-прежнему видите только вы.)
4. Нажмите **«Начать развертывание»**. Если снова попросит разрешения — повторите пункты 4–7 из шага 6.
5. Появится окно «Развертывание обновлено/создано» с полем **«URL веб-приложения»** — адрес вида
   `https://script.google.com/macros/s/AKfy…длинная-строка…/exec`. Нажмите **«Копировать»**.

✅ Проверка: откройте этот URL в браузере, дописав в конце `?action=availability`. Должен появиться текст, начинающийся с `{"ok":true,"acceptingOrders":true,…` — это свободные даты.

## Шаг 8. Вставить URL в сайт

Вариант А — сказать разработчику (Claude): пришлите URL, он вставит и опубликует.

Вариант Б — самому через GitHub:
1. Откройте в репозитории файл `config.js` → значок карандаша **«Edit this file»**.
2. Найдите строку `APPS_SCRIPT_URL: '',` и вставьте адрес между кавычками:
   `APPS_SCRIPT_URL: 'https://script.google.com/macros/s/AKfy…/exec',`
3. Внизу **«Commit changes…»** → выберите **«Commit directly to the main branch»** → **«Commit changes»**.
4. Через 1–2 минуты Vercel опубликует сайт.

✅ Должно быть: на сайте в блоке «Заявка» **пропала** пометка «демо-режим», календарь показывает даты из таблицы.

> Демо-переключатели `?demo=reset` и `?demo=paused` работают только в демо-режиме (пустой `APPS_SCRIPT_URL`). Чтобы показать «приём остановлен» на подключённом сайте — поставьте в таблице «Принимаем заявки» = `нет`.

## Шаг 9. Пробная заявка

1. Откройте сайт с телефона, выберите десерт, дату, заполните форму (в комментарии напишите «ТЕСТ»), отправьте.
2. Проверьте:
   - экран «Заявка A-0001 отправлена»;
   - в таблице на листе **«Заявки»** — новая строка;
   - на листе **«Даты»** у этой даты «Принято» = 1;
   - в Telegram-группе — сообщение «🧁 Новая заявка A-0001…»;
   - если прикрепляли фото — второе сообщение с фото и папка «<Название> — референсы» на Google Диске.
3. Удалите тестовую строку из «Заявок» (номер не повторится — следующий будет A-0002).

## Шаг 10. Нагрузочный тест на реальном адресе (по желанию, 5 минут)

Проверяет, что двое не займут одно последнее место. Нужен компьютер с Node.js 18+ (`node -v`).

1. В таблице на листе «Даты» выберите дату через неделю и поставьте ей **«Лимит заказов» = 3**.
2. В папке репозитория выполните (подставьте свой URL и эту дату):
   ```bash
   node tools/send-test-requests.mjs --url "https://script.google.com/macros/s/…/exec" --n 5 --date 2026-11-20
   ```
3. ✅ Ожидаемо: `«Новая» — 3, «Лист ожидания» — 2, ошибок — 0, дублей номеров — 0` и `РЕЗУЛЬТАТ: ПРОЙДЕН ✅`. В Telegram придут 5 сообщений.
4. Удалите 5 тестовых строк («Нагрузочный тест 1…5») и очистите лимит у даты.

## Шаг 11. Включить админку (ассортимент, фото, тексты — без разработчика)

Админка — страница **`…/admin.html`** (например, https://tort-anna.vercel.app/admin.html). Покупатели её не видят. Чтобы она заработала, нужно 4 вещи: новый код сервера, пароль, ключ GitHub для кнопки «Опубликовать» и (по желанию) вход через Google.

### 11.1. Обновить код сервера
0. Проверьте, что в «Свойствах скрипта» есть `SITE_URL`, `GITHUB_REPO`, `BAKERY_NAME` (шаг 5) — без первых двух новый код не даст опубликовать каталог.
1. Скопируйте свежий [`apps-script/Code.gs`](../apps-script/Code.gs) и вставьте вместо старого (как в шаге 3). Сохраните.
2. Выберите функцию **`setup`** → **▷ Выполнить**. Google может снова попросить разрешения — нажмите «Разрешить» (как в шаге 6).
   ✅ В таблице появятся листы **«Каталог», «Начинки», «Тексты», «Доступ»** — уже заполненные тем, что сейчас на сайте. (Есть ещё скрытый служебный лист «_Опубликовано» — его не трогайте.)
3. Обновите развертывание: **«Начать развертывание» → «Управление развертываниями» → карандаш → Версия: «Новая версия» → «Начать развертывание»**. Адрес не меняется.

### 11.2. Пароль для входа
1. **Настройки проекта → Свойства скрипта → Добавить свойство**: `ADMIN_PASSWORD` = придумайте пароль (от 8 символов, не «12345678»).
2. Сохраните. При первом входе пароль автоматически превратится в зашифрованный отпечаток (`ADMIN_PASSWORD_HASH`), а открытое свойство `ADMIN_PASSWORD` исчезнет — это нормально.
3. Дальше пароль меняется прямо в админке: вкладка **«Доступ» → «Пароль»**.

### 11.3. Ключ GitHub для кнопки «Опубликовать»
«Опубликовать» сохраняет каталог и фото в репозиторий сайта, и Vercel обновляет сайт примерно за минуту. Для этого нужен ключ с доступом **только к этому репозиторию**.
1. Откройте GitHub → аватар справа вверху → **Settings** → внизу слева **Developer settings** → **Personal access tokens → Fine-grained tokens** → **Generate new token**.
2. Заполните:
   - **Token name:** `ORDER FORGE — публикация каталога`
   - **Expiration:** 1 год (поставьте напоминание продлить)
   - **Repository access:** **Only select repositories** → выберите репозиторий сайта кондитерской
   - **Permissions → Repository permissions → Contents:** **Read and write** (остальное не трогать)
3. **Generate token** → скопируйте ключ (начинается с `github_pat_…`, показывается один раз).
4. В Apps Script: **Свойства скрипта → Добавить**: `GITHUB_TOKEN` = вставьте ключ. Сохраните.
   (Если репозиторий или ветка другие — добавьте `GITHUB_REPO` = `владелец/репозиторий`, `GITHUB_BRANCH` = `main`, а адрес сайта — в `SITE_URL`.)

> ⚠️ Ключ GitHub — такой же секрет, как токен бота: только в свойствах скрипта, нигде больше.

### 11.4. Вход через Google (по желанию, ~10 минут)
Без этого шага в админку входят по паролю. С ним — кнопкой «Войти через Google» по почтам из листа «Доступ».
1. Откройте **console.cloud.google.com** под своим Google-аккаунтом → вверху «Выбрать проект» → **«Создать проект»** → название `ORDER FORGE` → «Создать».
2. Меню ☰ → **APIs & Services (API и сервисы) → OAuth consent screen** (может называться **Google Auth Platform**):
   - **App name:** `<Название> — админка`, **User support email:** ваша почта;
   - **Audience (Аудитория):** **External**;
   - **Contact information:** ваша почта → «Создать».
   - На вкладке **Audience** нажмите **«Publish app» (Опубликовать приложение)** → «Подтвердить». Проверка Google для входа по почте не нужна, а без публикации войти смогут только «тестовые пользователи».
3. **Clients (Учётные данные) → Create client (Создать учётные данные → Идентификатор клиента OAuth)**:
   - **Application type:** **Web application**;
   - **Authorized JavaScript origins:** `https://tort-anna.vercel.app` (адрес вашего сайта, без `/` в конце);
   - «Создать» → скопируйте **Client ID** (вида `1234-abc….apps.googleusercontent.com`). Это **не секрет**.
4. Вставьте Client ID в **два** места:
   - в Apps Script: **Свойства скрипта** → `GOOGLE_CLIENT_ID` = Client ID;
   - на сайте: в `config.js` строка `GOOGLE_CLIENT_ID: ''` (или пришлите разработчику — вставит он).
5. Кто может входить: лист **«Доступ»** в таблице — почта Google, имя, «Доступ» = `да`. Владелец таблицы (тот, кто делал развертывание) входит всегда. То же самое можно делать в админке на вкладке «Доступ».

### 11.5. Проверка
1. Откройте `…/admin.html` → войдите паролем (и/или через Google).
2. Вкладка «Ассортимент» → у любого десерта «Изменить» → поменяйте цену → «Сохранить». Внизу появится «Не опубликовано изменений: 1».
3. «Опубликовать» → «ОК». Через ~1 минуту обновите сайт — цена изменилась. В Telegram придёт «📢 Каталог опубликован».
4. Верните цену и опубликуйте снова.

## Как обновить код (когда разработчик прислал новую версию `Code.gs`)

Админка сама подскажет, что пора: баннер **«Сервер устарел»** (версия сервера меньше, чем ждёт сайт).

Важно: после изменения кода сайт продолжит работать на **старой** версии, пока вы не обновите развертывание.

1. Вставьте новый код в `Код.gs`, сохраните.
2. `setup()` запускать не нужно: при первом запросе сервер сам донастроит таблицу (в «Журнале» — «Сервер обновлён»).
3. **«Начать развертывание» → «Управление развертываниями»**.
4. Выберите ваше развертывание → значок карандаша **«Изменить»**.
5. В поле **«Версия»** выберите **«Новая версия»** → **«Начать развертывание»**.

✅ URL остаётся прежним — в сайте ничего менять не нужно.

> Не создавайте «Новое развертывание» для обновлений: у него будет другой URL, и сайт продолжит ходить на старый.

## Если что-то пошло не так

| Что видно | Что делать |
|---|---|
| Сайт: «Не удалось загрузить свободные даты» | Откройте URL с `?action=availability`. Если просит войти в Google — в развертывании стоит доступ не «Все». Исправьте через «Управление развертываниями». |
| Ответ `"code":"not_configured"` | Не запускали `setup()` — шаг 6. |
| Заявка в таблице есть, а в Telegram нет | Откройте лист **«Журнал»** — там причина. Частые: неверный токен (`401 Unauthorized`), бот не в группе (`403 Forbidden: bot is not a member`), неверный chat_id (`400 chat not found`). |
| В «Журнале»: `group chat was upgraded to a supergroup` | Группа стала «супергруппой», её id сменился. В тексте ошибки есть `migrate_to_chat_id` (число, начинается с `-100`) — впишите его в `TELEGRAM_CHAT_ID`. |
| Изменили код, а на сайте старое поведение | Не обновили развертывание — раздел «Как обновить код». |
| «Превышено время ожидания» при первом запуске | Нажмите «Выполнить» ещё раз — первый запуск Google иногда медленный. |
| Админка: «Сервер устарел» или «не заданы свойства скрипта» | Вставьте свежий Code.gs и обновите развертывание («Новая версия») / добавьте названные свойства (шаг 5). |
| `setup()`: «Сначала добавьте свойства скрипта: SITE_URL, GITHUB_REPO» | Шаг 5: добавьте свойства и запустите `setup()` ещё раз. |
| Telegram: «⚠️ Лист «Заявки»: не найдены столбцы …» | Кто-то переименовал заголовок. Верните название в первой строке — до этого заявки идут в «Лист ожидания». Свои столбцы добавлять можно. |
| Админка: «Сервер ещё не обновлён для админки» | Вставьте новый Code.gs, `setup()`, обновите развертывание (шаг 11.1). |
| Админка: «Пароль ещё не задан» | Добавьте свойство `ADMIN_PASSWORD` (шаг 11.2). |
| «Опубликовать»: «Не задано свойство GITHUB_TOKEN» или «401 Bad credentials» | Ключ не вставлен или истёк — создайте новый (шаг 11.3). |
| «Опубликовать»: «403» или «Resource not accessible» | У ключа нет права Contents: Read and write на этот репозиторий. |
| «Войти через Google» не появляется | Нет `GOOGLE_CLIENT_ID` в `config.js` или в свойствах скрипта (шаг 11.4). |
