# Новая кондитерская: от анкеты до запуска

Эталон — этот репозиторий (демо «Регалия» — клиент №0). У каждого клиента свой репозиторий, собранный из
**файлов продукта** (`product-files.txt`, одинаковые у всех) и **файлов клиента** (из его анкеты `client.json`).
История демо к клиенту не попадает.

## 1. Анкета → `client.json` (15–30 мин)
- [ ] Скопировать `clients/example.client.json` → `clients/<ник>.client.json` и заполнить по анкете
  (подсказки — в поле `_fields`): название, латиница для логотипа, слоган, город; юр. данные оператора;
  десерты, начинки, тексты, контакты (`catalog` — та же структура, что `data/catalog.json`).
- [ ] Фото клиента — в папку рядом (например `clients/<ник>-photos/`): `hero`, по одному `<id десерта>`,
  `fillings`, `chef-hands`, `gift-box` (.png или .jpg). В `client.json`: `"photos": "<ник>-photos"`.
  Для тестового сайта можно `"photos": "demo"`.
- [ ] Реальные цифры для «О кондитерской» (`catalog.about.stats`) — не выдумывать; нет цифр — `[]`, блок скроется.
- [ ] Часовой пояс — пока только Москва (`Europe/Moscow`).
- [ ] **Свой дизайн:** файл темы `clients/<ник>.theme.css` (образец — `clients/example.theme.css`: палитра, арки, карточки)
  и в `client.json` — `"theme": { "file": "<ник>.theme.css", "metaColor", "iconBg", "iconFg", "iconAccent" }`.
  Тема меняет токены и детали, шрифты и разметка общие. Контраст текста — не ниже 4.5:1. Без темы — оформление «Регалии».

## 2. Сборка сайта (5 мин)
```bash
npm run new-client -- clients/<ник>.client.json ../<ник>-zakazy
```
Копирует файлы продукта, заполняет файлы клиента, сжимает фото, прогоняет `npm test` и `check-client`
(нет следов «Регалии», каталог и фото на месте) и делает первый коммит. Затем — пуш в пустой репозиторий,
который создали на GitHub (`git remote add origin … && git push -u origin main`).

## 3. Превью и согласование
- [ ] Vercel разработчика: Add New → Project → Import → Framework «Other» → Deploy. Сайт в демо-режиме (заявки в браузере).
- [ ] Партнёр показывает превью клиенту; правки — в `client.json` (тексты, бренд) или в каталоге
  (`data/catalog.json` + `npm run build-catalog`, **увеличить `version`**) → `npm run apply-client -- client.json`.
- [ ] Когда известен адрес сайта клиента — `siteUrl` в `client.json` + `apply-client` (превью ссылок, canonical, JSON-LD).

## 4. Передача и подключение (созвон партнёра с клиентом)
По «Инструкции партнёра»: GitHub клиента → **сделать репозиторий публичным** (бесплатный Vercel блокирует правки
соавторов в приватном) → Transfer клиенту → разработчик остаётся соавтором → Vercel клиента → Telegram →
Google-таблица и Apps Script (`docs/SETUP_GOOGLE.md`; значения свойств — `handover/ПОДКЛЮЧЕНИЕ.txt`) →
адрес `…/exec` в `config.js` → тестовая заявка. Памятки для клиента — в `handover/`.

## 5. Обновления продукта у клиента
В репозитории клиента (свежий `git pull` — клиент мог опубликовать каталог из админки):
```bash
node <путь-к-эталону>/tools/upgrade.mjs
git push
```
Меняются только файлы продукта и клиентские блоки страниц; каталог, фото и адрес Apps Script клиента — нет.
Если в `CHANGELOG.md` у версии пометка **[сервер]** — клиенту нужно вставить новый `Code.gs` и сделать
«Управление развертываниями → ✏️ → Новая версия» (админка сама покажет баннер «Сервер устарел»).

## Правила
- Контент (десерты, цены, фото, тексты) меняет клиент в админке. Разработчик правит `data/catalog.json` руками
  только для новых полей — и тогда **увеличивает `version`**, иначе сервер не увидит изменения.
- Код правится только в эталоне, к клиентам — через `upgrade`. Не правьте файлы продукта в репозитории клиента.
- `Code.gs` одинаковый у всех: всё, что зависит от клиента, — в свойствах скрипта (`SITE_URL`, `GITHUB_REPO`, `BAKERY_NAME`).
